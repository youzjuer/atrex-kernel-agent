Search guidance:
- The initial parent is a CUDA Graph tiled stable counting-sort implementation.
- It uses per-tile histograms, a block-prefix pass, a 256-entry expert prefix pass, and stable scatter.
- Valid directions include reducing launch/graph overhead, specializing small vs large token counts inside run(), reducing atomics in scatter, using block/warp-local prefix layouts, improving persistent scratch handling, and simplifying graph update overhead.
- Outside a declared stagnation escape, a strong parent may be refined with one isolated change at
  a time. During a forced stagnation escape (`metadata.stagnation_escape.required=true`), this
  local-refinement rule is suspended: Planner must name a different algorithm family, account for
  its full-array passes/launches/scratch traffic, and Executor must emit a complete architecture
  experiment based on the supplied seed. Constant-only, launch-bound-only, comment-only, and
  dead-code-only edits do not satisfy that requirement.
- CUDA shuffle groups must be hardware-warp aligned. Every lane that executes a `*_sync` intrinsic
  must be included in its mask; never emulate 72- or 96-thread logical groups by crossing warp
  boundaries with a single shuffle scan.
- Preserve proven cooperative launch dimensions and `grid.sync()` topology unless the plan checks
  residency, uniform barrier participation, all workload sizes, and a non-cooperative fallback.
- Preserve stability. Unstable sorting by expert id is incorrect even if counts match.
- Correctness is the hard gate; performance only matters after all 16 workloads pass.
- In `auto` or `cute_dsl` mode, CuTe DSL is a distinct architecture route rather than a syntax-only
  translation. Use CuTe layout algebra, vectorized copies, warp/block partitioning, and explicit
  stable rank construction. Account for JIT cache reuse and Python launch overhead on every shape.
- Do not combine a CuTe DSL wrapper with the parent's inline CUDA extension. A CuTe DSL child must
  remain a pure Python-language SOL solution with `languages: ["cute_dsl"]`.
